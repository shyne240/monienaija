## 1. Review rule

A6T11 reviews ADR-0047 through ADR-0052 (the A6 ADR range reserved by [`A6-IMPLEMENTATION-PLAN.md`](A6-IMPLEMENTATION-PLAN.md)) against the committed A6T01-A6T10 implementation artifacts. "Implementation-aligned" means the repository source/tests preserve the documented boundary. It does **not** mean an ADR has been approved for production, that a migration has run, that a partner is certified, or that the selected capability is active.

No signature, owner approval, risk acceptance, live database result, deployment, partner certification, or production activation is fabricated in this register.

## 5. Implementation-evidence vs. production-activation distinction

This register explicitly distinguishes the two evidence classes that A6T11 separates throughout its deliverables:

| Evidence class                     | What it proves                                                                                                                | What it does **not** prove                                                                                                    |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Implementation evidence**       | The committed A6 source code, migrations, tests, and contracts preserve the documented ADR boundary under automated validation | That the ADR has been approved, that the migration runs cleanly in a production database, or that the capability is deployable |
| **Production activation evidence** | Owner approval, live migration apply/rollback, route/credential enablement, partner certification, deployment drill              | Itself — these are decisions and operations, not source artifacts; A6T11 records the requirements but does not claim any are met |

Every A6T11 deliverable ([`A6-INTEGRATION-MATRIX.md`](A6-INTEGRATION-MATRIX.md), [`A6-ROUTE-EXPOSURE-AND-ROLLBACK.md`](A6-ROUTE-EXPOSURE-AND-ROLLBACK.md), [`A6-OPERATIONAL-RECOVERY-RUNBOOK.md`](A6-OPERATIONAL-RECOVERY-RUNBOOK.md), [`A6-EXIT-CHECKLIST.md`](A6-EXIT-CHECKLIST.md), [`A6-APPROVAL-PACKAGE.md`](A6-APPROVAL-PACKAGE.md), [`A6-A7-HANDOFF-PACKAGE.md`](A6-A7-HANDOFF-PACKAGE.md)) preserves this distinction.
