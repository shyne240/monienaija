## Test design and limits

- PostgreSQL fixture: 44 wallet transfers (one foreign institution), one C2C with initiation and claim journals, two posted canonical-service journals. 46 visible business transactions for the restricted principal.
- 40 wallet records share a millisecond but have distinct PostgreSQL microseconds. Seven-row keyset pages cover every scoped row once.
- Boundary records immediately before Lagos midnight, exactly at midnight, and at the next midnight prove half-open range semantics.
- Exact foreign reference returns no list items; foreign UUID/type returns 404; removing ACTIVE assignment revokes list and detail immediately.
- No-capability principal gets 403; unauthenticated gets 401; malformed dates/type/cursor/limit/reference rejected.
- Browser: Chromium 153 (Playwright + npm-provided serverless executable), full Vite SPA, real PostgreSQL-backed controller HTTP requests; **synthetic principal adapter and stub audit sink**. Not production login/session middleware evidence.
- Minimal fixture schema is not a migration test. Full backend suite, full application bootstrap, seeded-account sign-in, large-volume query plans, banking/funding projections remain unverified.
- Earlier full frontend run identified three assertions still expecting removed navigation. Updated those assertions to the unified contract; retained existing direct-component fee/trace/C2C tests elsewhere. Final full run is green; no tests were skipped.
