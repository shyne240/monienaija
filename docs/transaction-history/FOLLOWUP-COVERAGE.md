## Historical proposal (superseded for new Customer Funding by migration 0807)

`attribution-gaps.sql` identifies exact affected IDs/statuses on an authorized database without modifying anything. No real customer dataset was supplied; a production affected-record count cannot honestly be stated from synthetic fixtures.

Affected classes:

1. Customer funding requests with no posted journal, usually PENDING / REJECTED.
2. Agent funding/defunding requests with no posted journal, usually PENDING / REJECTED; institutional platform-pool execution may be deliberately unsupported.
3. Wallet transfers without posted journal attribution. Restricted staff do not get a current-wallet-derived grant.
4. Inbound observations/reviews without a receipt or explicit banking institution; suspense is not Bank to Wallet.

**Proposed safe migration (not applied automatically):** add an immutable request-time `institution_id` plus attribution kind (INSTITUTION / PLATFORM / UNRESOLVED), source evidence ID/version and captured timestamp to funding requests and transfer authorization records. Resolve and bind that context in the same transaction that creates the business request; bind it into approval fingerprints so checker execution cannot switch institution. Backfill only from original immutable journal/evidence/approved historical authorization with an unambiguous match. Never backfill from current affiliations. Leave ambiguous historical rows UNRESOLVED and invisible to institution-scoped readers; preserve a platform-only investigation queue and audited correction workflow. Require Product/Finance approval before exposing pending/rejected historical requests. This patch exposes only already-safe posted subsets, not guessed historical data.
