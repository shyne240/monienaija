# 09 — Delta from the 20261027 Audits

## Source baseline correction and scope

The 20261027 general discovery audit was based on `3428e37` and separately inspected older arena trees. This V2 audit runs on the actual integrated application `73eb1ca`, with the source branch docs-only tip `d93328d` verified as its child. Therefore, old counts and separate-arena integration caveats are not current integration facts unless still present in source.

## Resolved or materially changed

- **ARENA 2 agent-history / ARENA 3 route split:** the old audit treated UI and API as separate commits. They are now integrated on `73eb1ca`; closure reports provide historical PG and component evidence. Current browser-to-live API evidence remains absent.
- **Notification infrastructure and Admin management:** older 20261027 matrix did not include the integrated notification management screen as current capability. Source now contains the DB-backed registry, event/template governance, provider status/test-send and Admin workbench. The final closure report records full PG, unit and Admin test runs. Still no browser UAT/live provider delivery; maker/checker ratification is pending; manual retry remains deferred.
- **C2C beneficiary notifications / locator:** now in integrated source with transactional `cash_to_cash.created` enqueue, safe allowlisted payload, PHONE recipients and public locator. The audit does not redo implementation. `claimed` and `expired` event templates still have no outbox emitters per closure report; template presence is not a trigger.
- **C2C expiry trigger:** the Ordinary Agent audit found no production caller/trigger for `expireDueTransfers`. Current source has `AgentCashToCashExpiryWorker` with bounded scheduled polling and startup catch-up. However, `CASH_TO_CASH_EXPIRY_WORKER_ENABLED` defaults false, so current conclusion is operational config/monitoring unverified, not missing code. No decision on expired-funds disposition is reopened.
- **Admin notification authorization:** provider-status and test-send are function-gated; notification registry is governed. But delivery listing in `AdminNotificationController` still checks only workforce principal type. The older notification-finding bundle must be refined to this route-level distinction.
- **Updated inventory:** current source scan found 470 route decorator operations (vs old aggregate 460), 85 controllers, 179 services, 131 DTO files, 156 entity files, 100 migrations and 28 menu entries. Counts are source-only and non-comparable where prior audit used different snapshots or counting rules.
