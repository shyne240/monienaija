# P1.10 Customer Risk Profiles & Risk Assessments

## Scope

P1.10 adds internal customer risk-profile and manual risk-assessment metadata. It stores assessment dates, assessors, methods, risk levels, review dates, notes, current risk factors, and immutable assessment history.

This milestone does not implement AML rules, sanctions screening, transaction monitoring, fraud detection, machine learning, notifications, KYC verification, wallet logic, ledger logic, payments, transfers, reconciliation, or external integrations.

## Domain entities

| Entity                | Purpose                                                    |
| --------------------- | ---------------------------------------------------------- |
| `CustomerRiskProfile` | Current customer risk assessment and lifecycle status.     |
| `CustomerRiskFactor`  | Current factor set for the active assessment.              |
| `RiskProfileHistory`  | Append-only assessment snapshots.                          |
| `RiskFactorHistory`   | Append-only factor snapshots for every assessment version. |

A customer has one active risk-assessment profile. Reassessment updates the current profile with optimistic versioning, soft-deletes the prior current factor rows, inserts the new factor set, and preserves both assessment and factor history.

## Supported risk levels

- `LOW`
- `MEDIUM`
- `HIGH`
- `CRITICAL`

## Assessment fields

Each assessment stores:

- `assessmentDate`
- `assessedBy`
- `assessmentMethod`
- `overallRiskLevel`
- `reviewDueDate`
- `notes`
- At least one risk factor

Each factor stores:

- `category`
- `score`
- `weight`
- `remarks`

Scores must be non-negative. Weights must be greater than zero. `reviewDueDate` cannot be before `assessmentDate`.

## Lifecycle and history

Profiles have `ACTIVE` and `CLOSED` statuses. Closing a profile is terminal for that profile. Closed or soft-deleted profiles cannot be reassessed. A new active profile may be created after a prior profile is closed or soft-deleted.

Every create, reassessment, close, factor replacement, and history write is audited. Risk profile history records the complete assessment snapshot and version. Risk factor history records every factor for every assessment version.

## APIs

All routes use the global `/api/v1` prefix.

- `POST /customers/:id/risk-profile`
- `GET /customers/:id/risk-profile`
- `PATCH /customers/:id/risk-profile`
- `POST /customers/:id/risk-profile/reassess`
- `GET /customers/:id/risk-profile/history`

`PATCH` supports partial assessment updates, factor replacement, and profile closure. `POST /reassess` requires a complete assessment and factor set.

## PowerShell manual verification

### Setup

```powershell
$ErrorActionPreference = 'Stop'
$BaseUrl = 'http://localhost:3000/api/v1'
$Headers = @{ 'Content-Type' = 'application/json' }
$CustomerId = '<customer-uuid>'

npm ci
npm run migration:run
npm run start:dev
```

Use a second PowerShell window for API requests.

### 1. Create a risk profile with factors

```powershell
$ProfileBody = @{
  assessmentDate = '2026-08-01T00:00:00.000Z'
  assessedBy = 'risk-ops'
  assessmentMethod = 'MANUAL_REVIEW'
  overallRiskLevel = 'MEDIUM'
  reviewDueDate = '2026-12-01T00:00:00.000Z'
  notes = 'Initial manual risk assessment'
  factors = @(
    @{
      category = 'customer-profile'
      score = 10
      weight = 1
      remarks = 'Standard profile'
    },
    @{
      category = 'geography'
      score = 5
      weight = 0.5
      remarks = 'Review recorded'
    }
  )
  actor = 'risk-ops'
} | ConvertTo-Json -Depth 8

$Profile = Invoke-RestMethod `
  -Method Post `
  -Uri "$BaseUrl/customers/$CustomerId/risk-profile" `
  -Headers $Headers `
  -Body $ProfileBody

$Profile | ConvertTo-Json -Depth 12
$ProfileId = $Profile.id
```

Expected values:

- `overallRiskLevel` is `MEDIUM`.
- `factors` contains two entries.
- `version` is present.
- `reviewDueDate` is on or after `assessmentDate`.

A second profile creation for the same active customer must return `409`.

Invoke-RestMethod `

### 3. Reassess the customer

```powershell
$ReassessmentBody = @{
  assessmentDate = '2026-09-01T00:00:00.000Z'
  assessedBy = 'senior-risk-ops'
  assessmentMethod = 'MANUAL_REASSESSMENT'
  overallRiskLevel = 'HIGH'
  reviewDueDate = '2027-01-01T00:00:00.000Z'
  notes = 'Manual reassessment completed'
  factors = @(
    @{
      category = 'customer-profile'
      score = 30
      weight = 1
      remarks = 'Updated profile review'
    },
    @{
      category = 'manual-review'
      score = 80
      weight = 2
      remarks = 'Additional review factor'
    }
  )
  actor = 'senior-risk-ops'
} | ConvertTo-Json -Depth 8

$Reassessed = Invoke-RestMethod `
  -Method Post `
  -Uri "$BaseUrl/customers/$CustomerId/risk-profile/reassess" `
  -Headers $Headers `
  -Body $ReassessmentBody

$Reassessed | ConvertTo-Json -Depth 12
```

The profile ID must remain the same, the risk level must be `HIGH`, the factor set must be replaced, and the version must advance in PostgreSQL.

### 5. Read assessment and factor history

```powershell
$History = Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/customers/$CustomerId/risk-profile/history"

$History | ConvertTo-Json -Depth 12
```

The response must contain:

- At least one `assessments` entry with action `CREATED`.
- At least one `assessments` entry with action `REASSESSED`.
- Factor history entries for every factor in every assessment version.
- Previous assessment values preserved after reassessment.

### 6. Close the current profile

```powershell
$CloseBody = @{
  status = 'CLOSED'
  actor = 'risk-ops'
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Patch `
  -Uri "$BaseUrl/customers/$CustomerId/risk-profile" `
  -Headers $Headers `
  -Body $CloseBody | ConvertTo-Json -Depth 12
```

```powershell
try {
  Invoke-RestMethod `
    -Method Post `
    -Uri "$BaseUrl/customers/$CustomerId/risk-profile/reassess" `

    -Body $ReassessmentBody
  throw 'Closed risk profile unexpectedly reassessed'
} catch {
  $_.Exception.Response.StatusCode.value__

```

The reassessment request must return `409`.

### 7. Validate invalid assessment input

```powershell
$InvalidDateBody = @{
  assessmentDate = '2026-12-01T00:00:00.000Z'
  assessedBy = 'risk-ops'
  assessmentMethod = 'MANUAL_REVIEW'
  overallRiskLevel = 'LOW'
  reviewDueDate = '2026-11-01T00:00:00.000Z'
  factors = @(
    @{
      category = 'invalid'
      score = -1
      weight = 0
    }
  )
  actor = 'risk-ops'
} | ConvertTo-Json -Depth 8

try {
  Invoke-RestMethod `
    -Method Post `
    -Uri "$BaseUrl/customers/$CustomerId/risk-profile" `
    -Headers $Headers `
    -Body $InvalidDateBody
  throw 'Invalid risk profile unexpectedly succeeded'
} catch {
  $_.Exception.Response.StatusCode.value__
}
```

The request must return a validation error. Invalid review dates, empty factor arrays, negative scores, and zero weights are rejected.
