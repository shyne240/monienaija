The foreground was changed from `#D97706` to `#8C5600` against `#FFF3D9`; [targeted retests at both widths](evidence/acceptance-20261106/approvals-contrast-retest.json) report zero violations. Automated checks alone do not establish WCAG conformance or cover all states.
- **Visual:** Inspected the synthetic [Agent 320px initial state](evidence/acceptance-20261106/agent-initial-320.png) and [Notification 1440px initial state](evidence/acceptance-20261106/notification-initial-1440.png). The initial desktop screenshot showed missing-glyph squares for emoji in sidebar labels in this browser environment. Navigation now uses text labels without emoji; [320/1440 navigation retest](evidence/acceptance-20261106/nav-remediation-retest.json) had no overflow and the updated desktop screenshot was inspected. This is a narrow visual check, not a comprehensive populated-state review or Design approval.
- **Role authorization:** the full Jest run includes the 11-role menu-visibility suite and read-only/action guards. Its fixtures are not independent live role authorization checks; backend permissions, MFA, maker/checker and scoped records still require the consolidated live review.
- **CI:** run `42631452865` on `09dfc78` failed the real-PostgreSQL job; other jobs passed. The failed job log could not be downloaded in this environment (EOF), so the cause is unknown and must not be treated as resolved. Run `42638122669` on `6c05ac5` was still running its PostgreSQL job at last check, with the other three jobs successful. Neither run covers the subsequent review fixes.
