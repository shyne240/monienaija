# Batch 2: safety checkpoint — onboarding incomplete

This is **not** a completed Tier 1 onboarding implementation. The production tier evidence reader is unavailable and the existing pre-customer verification service accepts only fixed synthetic fixtures in `NODE_ENV=test`. It does not bind a customer's entered name/date of birth to provider-confirmed evidence or transfer that evidence to a customer. No production-ready provider contract, consent notice, reviewed policy or activation transaction exists. No synthetic result is represented as genuine evidence, and no successful onboarding or activation is claimed.

## Safety change

`POST /customers/registration` now returns 503 for otherwise-valid legacy completion requests. The service itself rejects before reading or consuming the verification token, creating a customer, credential, ledger account or wallet, or replaying an old idempotent result. This is an intentional breaking change for the legacy self-service API, including its DRAFT-only variant. The legacy OTP and verification endpoints remain available because the existing workforce customer workflow uses the resulting proof to verify a contact. The mobile registration screen explains unavailability and no longer collects phone, password or identity details for a journey that cannot safely complete. Existing records are untouched; no migration or runtime configuration change is included.

**The legacy self-service completion closure is not a global KYC activation guarantee.** The authorized administrative lifecycle can still activate a DRAFT customer with a verified phone without requiring KYC, and wallet creation has other workforce/service paths. Those pre-existing paths were not changed because this checkpoint preserves the administrative workflow and no safe, approved migration/exception policy for existing customers exists. They require a dedicated, concurrency-safe authorization and data-remediation decision before claiming that all activation is KYC-gated. Unrestricted database principals remain a bypass. Do not use this checkpoint as deployment authorization.
