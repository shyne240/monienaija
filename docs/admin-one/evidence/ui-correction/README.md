# UI correction: browser evidence

These are real Chromium captures of the local Vite UI connected to the actual Nest application and a separately created, synthetic, disposable PostgreSQL cluster. The data is illustrative; no real transaction records were created. The user's existing database, connection files and volumes were not used. Workers were disabled, Node outbound connections were guarded, browser requests outside the local test origin were blocked, and an API proxy allowed only reads and synthetic login (plus synthetic logout in the interaction run). Temporary test databases and servers were stopped afterwards.

- `dashboard-{1440,1280,768}.png`, `account-{1440,1280,768}.png`, and `customer-directory-1440.png` were recaptured after the final UI changes. The customer and session are synthetic.
- `manifest.json` records an earlier interaction pass on this same shell: all 28 destinations were clicked at 1440 across synthetic roles, all seven rail buttons at 1440 and 1280, sidebar collapse/expand, mobile drawer opening/Escape, account menu/Escape, the period selector, customer-preview focus restoration and a real synthetic logout. It reports no captured page/console errors, API failures or dashboard horizontal overflow. The later capture updated the screenshots, so the customer name in the manifest's interaction context is not the later screenshot's name.
- This is not a claim of exhaustive acceptance at every viewport: the 28-destination interaction pass was desktop only, and the empty synthetic database cannot verify populated charts, real financial data, all table states, all forms or all possible overflow/scroll traps. No staging, Windows execution, production access or external side effects were tested.
