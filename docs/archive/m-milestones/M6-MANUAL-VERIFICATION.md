# M6 Expanded Financial Products Manual Verification

This guide verifies the internal M6 reference, directory, beneficiary, virtual-account, quote, fee, and limit capabilities. It uses synthetic data only. No external bank synchronization, payment execution, authentication, or authorization is involved.

## Setup

```bash
cp .env.example .env
npm ci
docker compose up -d postgres
npm run migration:run
npm run start:dev
```

Set:

```bash
BASE_URL="http://localhost:3000/api/v1"
RUN_ID="$(date +%s)"
```

## 1. Bank directory CRUD and search

Create a bank:

```bash
BANK_RESPONSE="$(curl --fail-with-body -sS \
  -X POST "${BASE_URL}/banks" \
  -H 'Content-Type: application/json' \
  --data @- <<JSON
{
  "bankCode": "M6${RUN_ID: -3}",
  "bankName": "M6 Synthetic Bank ${RUN_ID}",
  "shortName": "M6 Bank",
  "nipSupported": true,
  "status": "ACTIVE"
}
JSON
)"
BANK_ID="$(echo "${BANK_RESPONSE}" | jq -er '.id')"
echo "${BANK_RESPONSE}" | jq .
```

Search and update it:

```bash
curl --fail-with-body -sS \
  "${BASE_URL}/banks?search=M6%20Synthetic&status=ACTIVE" | jq .

curl --fail-with-body -sS \
  -X PATCH "${BASE_URL}/banks/${BANK_ID}" \
  -H 'Content-Type: application/json' \
  --data '{"shortName":"M6 Updated"}' | jq .
```

Delete it and verify that a subsequent lookup returns `404`:

```bash
curl --fail-with-body -sS \
  -X DELETE "${BASE_URL}/banks/${BANK_ID}"

curl -sS -o /tmp/m6-bank.json -w 'HTTP status: %{http_code}\n' \
  "${BASE_URL}/banks/${BANK_ID}"
```

```bash
BENEFICIARY_RESPONSE="$(curl --fail-with-body -sS \
  -X POST "${BASE_URL}/beneficiaries" \
  -H 'Content-Type: application/json' \
  --data @- <<JSON
{
  "customerId": "m6-customer-${RUN_ID}",
  "nickname": "Main account",
  "bankCode": "001",
  "accountNumber": "1234567890",
  "accountName": "M6 Synthetic Customer",
  "type": "BANK_ACCOUNT"

JSON
)"
BENEFICIARY_ID="$(echo "${BENEFICIARY_RESPONSE}" | jq -er '.id')"
echo "${BENEFICIARY_RESPONSE}" | jq .
```

Repeat the same create request. It must return `409` and must not create a second beneficiary. Update, list, and delete:

```bash
curl --fail-with-body -sS \
  -X PATCH "${BASE_URL}/beneficiaries/${BENEFICIARY_ID}" \
  -H 'Content-Type: application/json' \
  --data '{"nickname":"Updated account"}' | jq .

curl --fail-with-body -sS \
  "${BASE_URL}/beneficiaries?customerId=m6-customer-${RUN_ID}" | jq .

curl --fail-with-body -sS \
  -X DELETE "${BASE_URL}/beneficiaries/${BENEFICIARY_ID}"
```

## 3. Virtual-account assignment and uniqueness

Create a wallet using the existing wallet endpoint, then assign a virtual account:

```bash
WALLET_RESPONSE="$(curl --fail-with-body -sS \
  -X POST "${BASE_URL}/wallets" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: m6-wallet-${RUN_ID}" \
  --data "{\"customerId\":\"m6-wallet-customer-${RUN_ID}\",\"currency\":\"NGN\"}")"
WALLET_ID="$(echo "${WALLET_RESPONSE}" | jq -er '.id')"

VIRTUAL_ACCOUNT_RESPONSE="$(curl --fail-with-body -sS \
  -X POST "${BASE_URL}/virtual-accounts" \
  -H 'Content-Type: application/json' \
  --data @- <<JSON
{
  "walletId": "${WALLET_ID}",
  "bankCode": "001",
  "accountNumber": "${RUN_ID}123456",
  "accountName": "M6 Wallet Account",
  "provider": "INTERNAL_PROVIDER"
}
JSON
)"
VIRTUAL_ACCOUNT_ID="$(echo "${VIRTUAL_ACCOUNT_RESPONSE}" | jq -er '.id')"
VIRTUAL_ACCOUNT_NUMBER="$(echo "${VIRTUAL_ACCOUNT_RESPONSE}" | jq -er '.accountNumber')"
VIRTUAL_ACCOUNT_REFERENCE="$(echo "${VIRTUAL_ACCOUNT_RESPONSE}" | jq -er '.reference')"
echo "${VIRTUAL_ACCOUNT_RESPONSE}" | jq .
```

A second active assignment for the same wallet and provider must return `409`. Lookup, list, and deactivate:

```bash
curl --fail-with-body -sS \
  "${BASE_URL}/virtual-accounts/lookup?provider=INTERNAL_PROVIDER&accountNumber=${VIRTUAL_ACCOUNT_NUMBER}" | jq .

curl --fail-with-body -sS \
  "${BASE_URL}/virtual-accounts?walletId=${WALLET_ID}" | jq .

curl --fail-with-body -sS \
  -X POST "${BASE_URL}/virtual-accounts/${VIRTUAL_ACCOUNT_ID}/deactivate" | jq .
```

The reference must be an `MN...` reference generated by the centralized payment-reference sequence.

## 4. Fee calculation

The fee engine is pure and does not persist or execute a payment:

```bash
curl --fail-with-body -sS \
  -X POST "${BASE_URL}/fees/calculate" \
  -H 'Content-Type: application/json' \
  --data @- <<'JSON' | jq .
{
  "amountMinor": "100000",
  "currency": "NGN",
  "paymentType": "TRANSFER",
  "flatFeeMinor": "100",
  "percentageBps": "100",
  "minimumFeeMinor": "500",
  "maximumFeeMinor": "2000",
  "vatBps": "750"
}
JSON
```

The expected result is a fee of `1100` minor units, VAT of `82`, and total of `101182` using integer arithmetic.

## 5. Limit evaluation

Limit evaluation is pure and does not record usage or block payment execution:

```bash
curl --fail-with-body -sS \
  -X POST "${BASE_URL}/limits/evaluate" \
  -H 'Content-Type: application/json' \
  --data @- <<JSON | jq .
{
  "customerId": "m6-customer-${RUN_ID}",
  "walletId": "${WALLET_ID}",
  "paymentType": "TRANSFER",
  "amountMinor": "60000",
  "singleTransactionLimitMinor": "50000",
  "dailyLimitMinor": "100000",
  "monthlyLimitMinor": "500000",
  "dailyUsedMinor": "50000",
  "monthlyUsedMinor": "100000"
}
JSON
```

The result should be `allowed: false` with single-transaction and daily-limit reasons.

## 6. Quote lifecycle and expiry

Create a future-dated quote:

```bash
QUOTE_RESPONSE="$(curl --fail-with-body -sS \
  -X POST "${BASE_URL}/quotes" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: m6-quote-${RUN_ID}" \
  --data @- <<JSON
{
  "paymentType": "TRANSFER",
  "amountMinor": "10000",
  "feeMinor": "100",
  "vatMinor": "8",
  "currency": "NGN",
  "expiresAt": "$(date -u -d '+10 minutes' '+%Y-%m-%dT%H:%M:%SZ')"
}
JSON
)"
QUOTE_ID="$(echo "${QUOTE_RESPONSE}" | jq -er '.id')"
echo "${QUOTE_RESPONSE}" | jq .
```

The quote should be `ACTIVE`, immutable, and have total `10108`. Mark it used:

```bash
curl --fail-with-body -sS \
  -X POST "${BASE_URL}/quotes/${QUOTE_ID}/use" | jq .
```

A second use attempt must return `USED` without changing the quote. Create a quote with an already elapsed `expiresAt`; it must be rejected at creation. A quote that passes its expiry while active must be reported as `EXPIRED` and cannot be used.

## 7. Reference checks

Verify that the virtual-account, quote, deposit, withdrawal, and new transfer records expose `MN...` references. References are backed by one shared sequence and registry, so they must not be duplicated across payment types.

## 8. Final verification

Run the existing finance verification report after the checks:

```bash
curl --fail-with-body -sS \
  "${BASE_URL}/internal/reconciliation/report" | jq .
```

M6 operations must not change wallet balances or create ledger journals. Quotes, fees, limits, bank records, beneficiaries, and virtual-account assignments are non-money-moving in this milestone.
