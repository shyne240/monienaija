# P1.8 Customer Authentication Credentials & Identity Recovery

## Scope

P1.8 adds internal metadata management for customer authentication credentials, password lifecycle, recovery workflows, MFA enrollment, trusted devices, recovery codes, and security events.

This milestone never stores plaintext passwords, tokens, MFA secrets, device fingerprints, or recovery codes. It stores hashes and lifecycle metadata only.

This milestone does not implement login, JWT, sessions, cookies, authentication middleware, authorization, OTP delivery, email, SMS, push, wallet operations, ledger operations, payments, transfers, or external identity providers.

## Domain entities

| Entity                             | Purpose                                                                                      |
| ---------------------------------- | -------------------------------------------------------------------------------------------- |
| `CustomerAuthenticationCredential` | Password credential metadata, expiry, failed-authentication counter, and account-lock state. |
| `PasswordHistory`                  | Append-only password hash and algorithm history.                                             |
| `PasswordResetRequest`             | Password recovery lifecycle metadata.                                                        |
| `PasswordResetToken`               | Hashed reset-token metadata and lifecycle.                                                   |
| `MfaEnrollment`                    | Customer MFA enrollment metadata.                                                            |
| `MfaMethod`                        | MFA method metadata without secrets or challenge execution.                                  |
| `TrustedDevice`                    | Device registration metadata with hashed fingerprint.                                        |
| `RecoveryCode`                     | Hashed recovery-code metadata and lifecycle.                                                 |
| `SecurityEventHistory`             | Append-only security event history.                                                          |

All domain records use UUIDs, PostgreSQL persistence, timestamps, soft deletion, and optimistic version columns where lifecycle updates occur. Append-only records have no update API.

## Password credentials

Credential creation accepts only:

- `passwordHash`
- `hashAlgorithm`
- `passwordVersion`
- Optional `passwordExpiresAt`
- Audit actor

No DTO contains a `password`, `plaintextPassword`, or password confirmation field. The service rejects hash values containing whitespace and exposes only hash algorithm and password version in credential views and audit values.

Password rotation stores the new hash metadata and appends a `PasswordHistory` record. Password expiry is represented by `passwordExpiresAt` and the computed `passwordExpired` view property. P1.8 does not compare or verify passwords.

## Failed authentication and unlock metadata

`POST /failed-attempt` increments the failed-authentication counter. At five failures the credential is marked `accountLocked`, records `lockedAt` and `lockReason`, and creates security events. This endpoint records metadata only; it is not a login endpoint and is not connected to authentication middleware.

`POST /unlock` clears the account lock and failed counter. It does not automatically change a credential’s lifecycle status.

## Password recovery

Password reset requests have a lifecycle:

```text
REQUESTED -> IN_PROGRESS -> COMPLETED
     |             |
     v             v
 EXPIRED       EXPIRED / CANCELLED / REJECTED
```

Reset tokens store only `tokenHash`, `tokenVersion`, status, issue time, and expiry. Tokens have their own lifecycle and are never returned as raw tokens. No token is delivered by email, SMS, push, or any other channel.

## MFA, devices, and recovery codes

MFA enrollments and methods store metadata only. Supported method types are `TOTP`, `AUTHENTICATOR_APP`, `SECURITY_KEY`, `SMS`, and `EMAIL`; no challenge, secret, OTP, or delivery integration is implemented.

Trusted devices store a device reference, display name, platform, and `deviceFingerprintHash`. Recovery codes store `codeHash` and version only. No raw code or fingerprint is accepted in a persisted field.

## Security events and audit

Every mutation creates an immutable audit event through the existing `AuditService`. Security event history records credential, password, lock, recovery, MFA, device, and recovery-code lifecycle metadata.

Audit entity types include:

- `CUSTOMER_AUTHENTICATION_CREDENTIAL`
- `PASSWORD_HISTORY`
- `PASSWORD_RESET_REQUEST`
- `PASSWORD_RESET_TOKEN`
- `MFA_ENROLLMENT`
- `MFA_METHOD`
- `TRUSTED_DEVICE`
- `RECOVERY_CODE`
- `SECURITY_EVENT_HISTORY`

## PowerShell manual verification

### Setup

```powershell
$ErrorActionPreference = 'Stop'
$BaseUrl = 'http://localhost:3000/api/v1'
$Headers = @{ 'Content-Type' = 'application/json' }
$CustomerId = '<customer-uuid>'

npm ci
npm run migration:run
npm run start:dev
```

Use a second PowerShell window for requests.

### 1. Create password credential metadata

```powershell
$CredentialBody = @{
  passwordHash = '$argon2id$v=19$m=65536,t=3,p=4$stored-hash'
  hashAlgorithm = 'ARGON2ID'
  passwordVersion = 1
  passwordExpiresAt = '2099-01-01T00:00:00.000Z'
  actor = 'auth-ops'
} | ConvertTo-Json

$Credential = Invoke-RestMethod `
  -Method Post `
  -Uri "$BaseUrl/customers/$CustomerId/authentication-credentials" `
  -Headers $Headers `
  -Body $CredentialBody

$Credential | ConvertTo-Json -Depth 8
$CredentialId = $Credential.id
```

The response must contain hash algorithm and password version metadata but no plaintext password field.

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/customers/$CustomerId/authentication-credentials/$CredentialId" | ConvertTo-Json -Depth 8

Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/customers/$CustomerId/authentication-credentials/$CredentialId/password-history" | ConvertTo-Json -Depth 8
```

### 2. Rotate password metadata

```powershell
$RotationBody = @{
```

### 4. Create a password reset request and token hash

```powershell
$ResetRequestBody = @{
  credentialId = $CredentialId
  expiresAt = '2099-01-01T00:30:00.000Z'
  reason = 'Customer recovery request'
  actor = 'recovery-ops'
} | ConvertTo-Json

$ResetRequest = Invoke-RestMethod `
  -Method Post `
  -Uri "$BaseUrl/customers/$CustomerId/password-reset-requests" `
  -Headers $Headers `
  -Body $ResetRequestBody

$ResetRequest | ConvertTo-Json -Depth 8
$ResetRequestId = $ResetRequest.id
```

```powershell
$TokenBody = @{
  tokenHash = 'sha256-token-hash-only'
  tokenVersion = 1
  expiresAt = '2099-01-01T01:00:00.000Z'
  actor = 'recovery-ops'
} | ConvertTo-Json

$ResetToken = Invoke-RestMethod `
  -Method Post `
  -Uri "$BaseUrl/customers/$CustomerId/password-reset-requests/$ResetRequestId/token" `
```

### 8. Validate plaintext rejection and UUID validation

```powershell
$InvalidCredentialBody = @{
  password = 'plaintext-password'
  passwordHash = 'hash-value'
  hashAlgorithm = 'BCRYPT'
  passwordVersion = 1
  actor = 'auth-ops'
} | ConvertTo-Json

try {
  Invoke-RestMethod `
    -Method Post `
    -Uri "$BaseUrl/customers/$CustomerId/authentication-credentials" `
    -Headers $Headers `
    -Body $InvalidCredentialBody
  throw 'Unexpected plaintext credential DTO success'
} catch {
  $_.Exception.Response.StatusCode.value__
}

try {
  Invoke-RestMethod `
    -Method Get `
    -Uri "$BaseUrl/customers/not-a-uuid/authentication-credentials"
  throw 'Unexpected UUID validation success'
} catch {
  $_.Exception.Response.StatusCode.value__
}
```

Both requests must return validation errors. There is no login endpoint, JWT, session, cookie, authorization, or notification delivery endpoint in P1.8.
