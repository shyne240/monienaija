# P1.9 Customer Compliance Case Management

## Scope

P1.9 adds internal metadata-only compliance case management. It stores case lifecycle, assignments, comments, evidence references, and append-only case history.

This milestone does not perform KYC verification, AML screening, sanctions checks, transaction monitoring, OCR, workflow automation, notifications, authentication, authorization, wallet operations, ledger operations, payments, transfers, reconciliation, or external integrations.

## Entities

| Entity                     | Purpose                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------- |
| `CustomerComplianceCase`   | Case identity, category, severity, lifecycle, assignment, resolution, and timestamps. |
| `ComplianceCaseHistory`    | Append-only case lifecycle and mutation history.                                      |
| `ComplianceCaseAssignment` | Append-only assignment records.                                                       |
| `ComplianceCaseComment`    | Immutable case comments.                                                              |
| `ComplianceCaseEvidence`   | Metadata-only evidence references with no binary storage.                             |

## Lifecycle rules

The supported status transitions are:

| Current            | Allowed next statuses                                                 |
| ------------------ | --------------------------------------------------------------------- |
| `OPEN`             | `UNDER_REVIEW`, `PENDING_CUSTOMER`, `ESCALATED`, `RESOLVED`, `CLOSED` |
| `UNDER_REVIEW`     | `PENDING_CUSTOMER`, `ESCALATED`, `RESOLVED`, `CLOSED`                 |
| `PENDING_CUSTOMER` | `UNDER_REVIEW`, `ESCALATED`, `RESOLVED`, `CLOSED`                     |
| `ESCALATED`        | `UNDER_REVIEW`, `RESOLVED`, `CLOSED`                                  |
| `RESOLVED`         | `CLOSED`                                                              |
| `CLOSED`           | None                                                                  |

Closed cases cannot be reopened or modified. Resolution updates are recorded independently in case history. Closing a case sets `closedAt`.

## Assignments

Assignments are append-only. Each assignment change creates a new assignment record and updates the case’s current `assignedTo` field. Existing assignment records are never edited.

## Comments and evidence

Comments are append-only and require an actor. Evidence stores only:

- `documentName`
- `documentType`
- `reference`
- `uploadedBy`
- `uploadedAt`

No binary content, OCR result, storage key, or external document integration is stored.

## History and audit

History actions include:

- `CASE_CREATED`
- `STATUS_CHANGED`
- `ASSIGNMENT_CHANGED`
- `CASE_CLOSED`
- `RESOLUTION_UPDATED`
- `COMMENT_ADDED`
- `EVIDENCE_ADDED`

Every case, assignment, comment, evidence, and history mutation creates an immutable audit event in the same transaction using the existing `AuditService`.

## PowerShell manual verification

### Setup

```powershell
$ErrorActionPreference = 'Stop'
$BaseUrl = 'http://localhost:3000/api/v1'
$Headers = @{ 'Content-Type' = 'application/json' }
$CustomerId = '<customer-uuid>'

npm ci
npm run migration:run
npm run start:dev
```

Use a second PowerShell window for requests.

### 1. Create a compliance case

```powershell
$CaseBody = @{
  caseNumber = "case-$([guid]::NewGuid().ToString('N').Substring(0, 10))"
  category = 'MANUAL_REVIEW'
  severity = 'MEDIUM'
  actor = 'compliance-ops'
} | ConvertTo-Json

$Case = Invoke-RestMethod `
  -Method Post `
  -Uri "$BaseUrl/customers/$CustomerId/compliance-cases" `
  -Headers $Headers `
  -Body $CaseBody

$Case | ConvertTo-Json -Depth 8
$CaseId = $Case.id
```

Expected values:

- `status` is `OPEN`.
- `openedBy` is `compliance-ops`.
- `closedAt` is null.
- `version` is present.
- No screening, OCR, notification, wallet, ledger, payment, or transfer action occurs.

### 2. Read the case and initial history

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/customers/$CustomerId/compliance-cases" | ConvertTo-Json -Depth 8

Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/customers/$CustomerId/compliance-cases/$CaseId" | ConvertTo-Json -Depth 8

Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/customers/$CustomerId/compliance-cases/$CaseId/history" | ConvertTo-Json -Depth 12
```

History must contain `CASE_CREATED`.

### 3. Assign and reassign the case

```powershell
$AssignmentBody = @{

  actor = 'compliance-lead'
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "$BaseUrl/customers/$CustomerId/compliance-cases/$CaseId/assignment" `

  -Body $AssignmentBody | ConvertTo-Json -Depth 8
```

```powershell
Invoke-RestMethod `

  -Headers $Headers `
  -Body (@{

  -Uri "$BaseUrl/customers/$CustomerId/compliance-cases/$CaseId/assignments" | ConvertTo-Json -Depth 8
```

### 6. Close the case and verify closed-case protection

```powershell
Invoke-RestMethod `
  -Method Patch `
  -Uri "$BaseUrl/customers/$CustomerId/compliance-cases/$CaseId" `
  -Headers $Headers `
  -Body (@{
    status = 'CLOSED'
    actor = 'compliance-lead'
  } | ConvertTo-Json) | ConvertTo-Json -Depth 8
```

```powershell
try {
  Invoke-RestMethod `
    -Method Patch `
    -Uri "$BaseUrl/customers/$CustomerId/compliance-cases/$CaseId" `
    -Headers $Headers `
    -Body (@{
      status = 'OPEN'
      actor = 'compliance-lead'
    } | ConvertTo-Json)
  throw 'Closed case unexpectedly reopened'
} catch {
  $_.Exception.Response.StatusCode.value__
}
```

The reopening request must return `409`. Comments, evidence, and assignment changes after closure must also return `409`.

### 7. Verify history and audit events

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/customers/$CustomerId/compliance-cases/$CaseId/history" | ConvertTo-Json -Depth 12

Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/internal/audit?entityType=CUSTOMER_COMPLIANCE_CASE&entityId=$CaseId&limit=100" | ConvertTo-Json -Depth 12
```

History must include creation, assignment changes, comment, evidence, status changes, resolution update, and case closure. Audit results must include case, assignment, comment, evidence, and history mutations.

### 8. Verify duplicate case number and UUID validation

```powershell
try {

```

Both requests must return errors. The case-number request must return `409`.
