# P1.0 Product Governance Manual Verification

This guide verifies product, regulatory, launch, and operational governance records using PowerShell. It does not create wallets, post journals, execute transfers, process payments, or call external systems.

## Setup

```powershell
$ErrorActionPreference = 'Stop'
$BaseUrl = 'http://localhost:3000/api/v1'

npm ci
npm run migration:run
npm run start:dev
```

## 1. Create the product profile

```powershell
$Headers = @{ 'Content-Type' = 'application/json' }
$Profile = @{
  kind = 'PRODUCT_PROFILE'
  recordKey = 'monienaija-core'
  name = 'MonieNaija Core Product'
  status = 'DRAFT'
  version = 1
  immutableRecord = $true
  actor = 'product-owner'
  payload = @{
    productName = 'MonieNaija'
    country = 'NG'
    baseCurrency = 'NGN'
    description = 'Controlled internal mobile-money product'
  }
} | ConvertTo-Json -Depth 8

$ProfileResponse = Invoke-RestMethod `
  -Method Post `
  -Uri "$BaseUrl/internal/product-governance/records" `
  -Headers $Headers `
  -Body $Profile

$ProfileResponse | ConvertTo-Json -Depth 8
```

## 2. Create scope and launch-envelope records

```powershell
$Scope = @{
  kind = 'PRODUCT_SCOPE'
  recordKey = 'p1-initial-scope'
  name = 'P1 Initial Product Scope'
  status = 'APPROVED'
  version = 1
  immutableRecord = $true
  actor = 'product-owner'
  payload = @{
    included = @('wallets', 'internal-transfers', 'controlled-payments')
    excluded = @('authentication', 'kyc', 'external-rails')
  }
} | ConvertTo-Json -Depth 8

$Envelope = @{
  kind = 'LAUNCH_ENVELOPE'
  recordKey = 'pilot-envelope'
  name = 'Controlled Pilot Envelope'
  status = 'DRAFT'
  version = 1
  immutableRecord = $true
  actor = 'risk-owner'
  payload = @{
    countries = @('NG')
    currencies = @('NGN')
    maxPilotCustomers = 100
    reversible = $true
  }
} | ConvertTo-Json -Depth 8

Invoke-RestMethod -Method Post -Uri "$BaseUrl/internal/product-governance/records" -Headers $Headers -Body $Scope | ConvertTo-Json -Depth 8
Invoke-RestMethod -Method Post -Uri "$BaseUrl/internal/product-governance/records" -Headers $Headers -Body $Envelope | ConvertTo-Json -Depth 8
```

## 3. Add launch-governance records

Create representative records for each governance requirement. The same endpoint is used with a different `kind`:

```powershell
$Kinds = @(
  'SUPPORTED_COUNTRY',
  'SUPPORTED_CURRENCY',
  'PILOT_COHORT',
  'CUSTOMER_SEGMENT',
  'REGULATORY_JURISDICTION',
  'REGULATORY_REQUIREMENT',
  'BUSINESS_CAPABILITY',
  'FEATURE',
  'FEATURE_FLAG',
  'LAUNCH_GATE',
  'GONO_GO_CRITERION',
  'PRODUCT_RISK',
  'OPERATIONAL_OWNER',
  'PARTNER',
  'PARTNER_EVALUATION',
  'SERVICE_LEVEL_OBJECTIVE',
  'SERVICE_LEVEL_INDICATOR',
  'ROLLBACK_STRATEGY',
  'SUCCESS_METRIC',
  'PRODUCT_CONFIGURATION',
  'LAUNCH_CHECKLIST',
  'PRODUCT_VERSION_METADATA',
  'PRODUCT_REQUIREMENT'
)

$Index = 0
foreach ($Kind in $Kinds) {
  $Index++
  $Record = @{
    kind = $Kind
    recordKey = "p1-$($Kind.ToLower())-$Index"
    name = "P1 $Kind"
    status = 'APPROVED'
    version = 1
    immutableRecord = $true
    actor = 'governance-owner'
    payload = @{
      evidence = "synthetic-evidence-$Index"
      owner = 'governance-owner'
      reviewStatus = 'approved'
    }
  } | ConvertTo-Json -Depth 8

  Invoke-RestMethod `
    -Method Post `
    -Uri "$BaseUrl/internal/product-governance/records" `
    -Headers $Headers `
    -Body $Record | Out-Null
}
```

## 4. Verify governance report

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/internal/product-governance/report" | ConvertTo-Json -Depth 8

Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/internal/product-governance/records" | ConvertTo-Json -Depth 8
```

The report must show counts by governance kind and no unexpected blocked records.

## 5. Verify launch readiness

```powershell
$Readiness = Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/internal/product-governance/readiness"

$Readiness | ConvertTo-Json -Depth 8
```

Readiness must return `PASS` when the required evidence records are approved. Missing evidence returns `WARNING`; blocked evidence returns `FAIL`.

## 6. Verify immutability and audit

Attempt to update an immutable record:

```powershell
$Update = @{ name = 'Attempted Change'; actor = 'operator' } | ConvertTo-Json

try {
  Invoke-RestMethod `
    -Method Patch `
    -Uri "$BaseUrl/internal/product-governance/records/$($ProfileResponse.id)" `
    -Headers $Headers `
    -Body $Update
  throw 'Immutable update unexpectedly succeeded'
} catch {
  $_.Exception.Response.StatusCode.value__
}
```

The request must return a conflict response. Verify the audit trail:

```powershell
Invoke-RestMethod `
  -Method Get `
  -Uri "$BaseUrl/internal/audit?entityType=PRODUCT_GOVERNANCE_RECORD&limit=100" | ConvertTo-Json -Depth 8
```

Creation and mutable updates must have audit events. Immutable update attempts must not change the record.
