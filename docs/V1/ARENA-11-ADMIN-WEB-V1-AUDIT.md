2. **Institution scope matters beyond menu visibility.** Customer record, transaction, ledger, bank/reconciliation, and institution access require server-side record scope. Existing history evidence demonstrates useful foreign-institution 404 behavior on selected products. Do not infer all screens are isolated from menu visibility alone.

History evidence demonstrates reference-based lookup for selected products; agent, customer, institution and support workflows still need a usability pass with real business identifiers. A routine agent should not need to paste a UUID when a customer number, application reference, transaction reference or institution code is available.
4. **Actionability is unevenly proven.** Component tests establish rendered buttons and mock action responses. The table records where there is no real API/DB acceptance that a staff member can complete the action from the screen. In particular, do not treat a page with an endpoint or a disabled control as a completed workflow.

The same semantic check is still needed across limits, fees, VAT, commission, reward, bank balances and provider status.
