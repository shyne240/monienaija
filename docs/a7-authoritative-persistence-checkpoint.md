# A7 authoritative persistence checkpoint

This is a **partial, nonfinancial** persistence boundary, not financial lifecycle acceptance.
`A7ProductPersistenceService` is registered and exported from the A7 command module; it is not a public HTTP API and does not replace the legacy command and lifecycle service contracts. New commands are created in `LIFECYCLE_PENDING`, and the only reachable state change today is cancellation. Admission is deliberately unavailable even with an A4 allow decision: the A7 profile's recheck obligations do not yet have a transaction-bound implementation for this path. No execution or posting is enabled. The stored execution-receipt field is constrained to null.

A customer session is validated through the existing session service and rechecked with its credential in the write transaction. The A2 authorization evaluator is invoked for self access to the individual command and its actual decision is recorded in the existing immutable audit log in that transaction. The active A3 binding, ownership, wallet and ledger account are checked together under locks. An optional existing A4 decision must match the customer, operation and binding evidence; absent policy remains null and never permits admission. Optional observed inbound funding must resolve to the bound active virtual account, and provider/reference uniqueness prevents multiple commands for the same observed arrival. This does not establish that funds may be posted.

Commands and transition history are immutable; lifecycle updates use a version, row lock and transaction-linked transition record. Customer-scoped request keys and lifecycle-scoped transition keys detect conflicting replays. SQL triggers prevent lifecycle changes outside the supported transition graph. Legacy A7 consumer ports that previously fabricated authorization, policy, binding maps, command/lifecycle outcomes, consent or notification delivery now fail closed because their old contracts cannot faithfully express the new records. Legacy lifecycle replay also fails closed rather than recreating a record from a response or caller's prior state. The existing outbound-direction guard remains in place.

Remaining work within the requested persistence scope: adapt the existing A7 command/lifecycle consumers to persisted records rather than leaving their incompatible legacy views unavailable; implement and test legitimate policy obligation rechecks and any additional evidence-backed transitions; expand tests for policy evidence and transition coverage. Do not treat this checkpoint as a complete implementation or enable financial execution based on it. No ledger integration, production provider verification, or institutional integration is included.

Validation: guarded, disposable PostgreSQL integration run `a7p06` passed 44 tests across the new persistence, existing financial commitment, and migration-readiness suites. The subsequently expanded focused persistence run `a7p07` passed 5 tests, including concurrent command and observation uniqueness, transition replay, stale/conflicting requests, real stored authorization evidence, and fail-closed legacy ports. TypeScript and lint for the changed files passed. Test authority/KYC fixtures are controlled test evidence, not production provider verification.
