What the chain suite proves on a genuinely empty database
---------------------------------------------------------
1. The filesystem glob is not silently matching nothing (migration count sanity check first).
2. The database starts empty, then every migration executes in ONE atomic chain from empty —
   so a fresh production/shadow database reaches head in a single run with no manual ordering.
3. Zero migrations are left pending afterwards, and `migrations` records exactly the discovered
   set (no drift between disk and ledger, no duplicate entries).
4. The notification registry seeds during the real migration, including the locked SECURITY rows.
5. Every foreign key exists in a VALIDATED state (`convalidated`), and no relation name is declared
   twice between constraints and indexes.
6. A5/A6T08/B2 column and constraint contracts survive the chain (snake_case-only accounting unit
   column, reversal-reference constraint, consumer/webhook identity uniqueness, reserved-word
   quoting).
7. TypeORM entity metadata matches the migrated schema (no phantom column the entity would need).

Historical-data upgrade (the part that is not a greenfield check)
-----------------------------------------------------------------
test/migration-chain.integration.spec.ts also upgrades governed wallet ownership WITH data present:
- an unambiguous historical reference is canonicalised in place, and ownership itself is NOT
  resolved by the migration (it has to be established through the governed path afterwards);
- a historical canonical collision is rejected atomically: no wallet is merged, no row is deleted,
  and the database is left exactly as it was (no partial canonicalisation).
The institutional-scope CHECK from 1785753600401 is what makes this possible: an upgrade cannot
produce a half-attributed account, because `(institutional_scope='INSTITUTION') =
(institution_id IS NOT NULL)` is enforced by the database, not by application code.

the migration ledger, so a deployment that ships code expecting a migration which is not on disk
(or the reverse) fails here rather than in production.
