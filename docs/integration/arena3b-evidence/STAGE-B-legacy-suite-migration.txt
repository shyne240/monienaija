New shared helper
-----------------
test/support/cash-out-lifecycle-fixture.ts — `startGovernedDesk()` returns a harness that
provisions the institutional context (affiliation, wallet attribution, agent credential/session,
customer enrolment) and issues real intent-bound Cash-Out OTPs through AgentDeskOtpService. It is
a thin composition of the existing fixtures; it adds no production bypass.

Contract corrections made (all fail-closed)
-------------------------------------------
- Cash-Out issuance now requires the intent context (amountMinor + currency + operationKey) and the
  redemption must use that same operation key. Suites that issued a context-free challenge were
  updated (class B: obsolete request contract).
- A WALLET_TO_CASH challenge is bound to its cash_out_intent (the challenge's own session column is
  NULL; the canonical principal uses the intent id). Assertions on the legacy customer-plane session
  were replaced with the real binding.
- A legacy purpose-NULL challenge can no longer claim: it has no transfer binding and no
  authenticated Agent session, so the claim is refused and the transfer stays UNCLAIMED. Previously
  the test asserted a successful legacy claim; that convention is no longer supported.
- Cash-to-Cash funding requires the controlled approved policy in-suite; unclaimed liability lands on
  the institution's suspense account (never the legacy global `CASH_TO_CASH-UNCLAIMED-NGN` row).
- A Cash-to-Cash claim now carries `claimantPrincipal` (authenticated Agent session) and its OTP is
  issued through `AgentDeskOtpService.issue({purpose:'CASH_TO_CASH_CLAIM'})` with the redemption
  operation key equal to the claim idempotency key.
- Every migrated suite builds its module with
  `overrideCashToCashFundingPolicy(governedDeskProviderOverride(builder, smsProvider), policy)`;
  the workforce double and `A2_WORKFORCE_CONFIG` override were deleted everywhere (a token double
  cannot supply role-derived function scopes). Workforce HTTP calls use real
  `governed.fixture.workforce()` tokens.
- v1-agent-05 keeps its PIN-security focus but its Cash-Out leg (`cashOutAs`) now runs the governed
  lifecycle; the suite truncates tables per test, so the institutional context is provisioned in
  `beforeEach`. The shared harness reuses an existing ACTIVE agent credential (the suite logs in over
  HTTP first) instead of inserting a duplicate.

v1-agent-history-01 — the former blocker, now green (17/17)
-----------------------------------------------------------
The suite no longer mocks A2WorkforceSessionService. It runs the real workforce service, so the
institution maker-checker flow works. Specific corrections:

- Class B (obsolete request contract): the Cash-Out legs (cases 4 and 15) issue governed
  WALLET_TO_CASH intents in `ah01-out-*` / `ah01-c15-*` operation keys; case 6 claims through a
  governed CASH_TO_CASH_CLAIM issuance with `claimantPrincipal`.
- Class B (obsolete fixture): `agentLoginToken` used to INSERT a second ACTIVE credential; it now
  installs the password on the single ACTIVE credential the governed provisioning created (the
  schema allows exactly one).
- Class B (obsolete fixture): `agentBundle` seeds float from the institution's settlement float
  instead of the platform funding pool, because an institution-attributed agent wallet can only
  join journals of its own institution.
- Class A (obsolete expectation, funding rail boundary): AGENT_FUNDING / AGENT_DEFUNDING are
  platform-rail operations (`AGENT_FUNDING_POOL-NGN` carries no institution classification, so the
  institutional ledger contract fails closed for an attributed agent). Cases 2, 3, 11 and 13 use a
  new `platformAgentBundle()`; case 10 proves isolation across the two rails (agent A = platform
  funding, agent B = institutional Cash-to-Cash).
- Class A (obsolete expectation): cases 7 and 8 mixed funding and institutional flows on ONE agent.
  That combination is no longer reachable, so both now stack only institutional flows (two
  Cash-to-Cash initiations + a cash-in) and assert the same chronological/pagination properties.
- Class B: the internal workforce history route requires the real `agent.view` function, so case 13
  uses the AGENT_NETWORK_MANAGER token instead of the literal `workforce-operator` string, and 12
  uses the FINANCE_AUDITOR token. Suspension now revokes every ACTIVE session for the agent (the
  governed fixture legitimately holds more than one), so 13 asserts "all REVOKED, at least one".

No production behaviour was changed to make any of these pass.
