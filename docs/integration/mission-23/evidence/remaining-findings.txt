== Reachability / production exposure ==
   1. No application or test source imports the glob or minimatch packages:
        grep -rnE "from '(glob|minimatch)'|require\('(glob|minimatch)'\)" src/ test/ --include=*.ts
        -> 0 matches (re-run and confirmed)
      A loose grep for the substring "glob" does match 22 lines, but every one of them is the
      word "global"/"globally" inside a comment or an unrelated identifier (e.g. "global
      checker inbox"). None of them imports or calls the package.
   2. The only production consumer is TypeORM's entity/migration file discovery.
      Configured patterns are compile-time constants that cannot carry request data:
        43:    entities: [`${__dirname}/../**/*.entity{.ts,.js}`],
        44:    migrations: [`${__dirname}/../migrations/*{.ts,.js}`],
   3. glob/minimatch therefore only process paths derived from the deployed file layout.
      GHSA-3g3m-2fjr-6pw4 (glob/AbortSignal traversal) and GHSA-g3hv-75wg-m249
      (minimatch globparts amplification) both require an attacker-influenced pattern
      and, for the former, an abort signal on a caller-controlled traversal.
      Neither is reachable from an HTTP request in this application.
   4. Residual risk: LOW in this deployment. No request path reaches the vulnerable code
      with attacker-controlled input.

== Why it was not fixed in this mission ==
   The only fix npm offers is typeorm 0.3.31 -> 1.1.2, a semver-major ORM upgrade.
   Mission 23 boundaries: "Do not expand this mission into unrelated dependency upgrades"
   and "no product-policy changes". An ORM major upgrade would touch migrations, entity
   mapping and the financial read/write paths and is not a security-remediation step for
   this advisory chain. Recorded as a follow-up for a dedicated dependency-upgrade mission.
